### 技術背景：SKILL.md Frontmatter 規格

來源為 Anthropic 官方文件，三個關鍵欄位：
- `name`：必須與目錄名稱一致（技能識別符）
- `description`：≤1024 字元，Claude 判斷是否自動載入的**唯一依據**
- `disable-model-invocation: true`：強制使用者透過 `/skill-name` 手動呼叫，技能不進入 Claude 自動決策

## 3. 程式碼中發現的特殊事項

### obsidian-vault — Hardcoded 路徑

`obsidian-vault/SKILL.md` 中的 Vault 路徑完全 hardcode：

```
/mnt/d/Obsidian Vault/AI Research/
```

這是 Matt Pocock 個人 Windows 環境（WSL2 掛載點）的路徑。所有搜尋指令（`find`、`grep -rl`）都以此絕對路徑為基礎。其他使用者安裝此技能後，若不手動修改 SKILL.md，技能將完全無法運作。這是 repo 中通用性最低的一個技能。

### scaffold-exercises — pnpm ai-hero-cli internal lint

`scaffold-exercises/SKILL.md` 的核心工作流的第 4 步驟為：

```
Run lint - `pnpm ai-hero-cli internal lint` to validate
```

`ai-hero-cli` 是 Matt Pocock 為 aihero.dev 課程平台開發的**個人工具**，在 npm 上沒有公開套件（或未在文件中說明如何安裝）。這意味著：
- 此技能**僅在 Matt Pocock 的課程 repo 內有效**
- 其他使用者無法通過第 4 步的 lint 驗證
- 技能本身缺乏關於此依賴的來源說明

### github-triage — AI 免責聲明強制要求

每個 `github-triage` 產生的 GitHub Issue comment，**必須在第一行**包含：

```markdown
> *This was generated by AI during triage.*
```

這是 SKILL.md 中的明確規範（AI Disclaimer 段落），目的是透明度。然而：
- 若 Claude 未遵守此格式（例如漏掉免責聲明），沒有任何程式化機制能強制執行
- 完全依賴 Claude 遵循指令，屬於 soft constraint

### domain-model 與 ubiquitous-language — disable-model-invocation: true

這兩個技能設定 `disable-model-invocation: true` 的原因有充分說明：
- **副作用性**：會修改 codebase 文件（`CONTEXT.md`、`docs/adr/*.md`、`UBIQUITOUS_LANGUAGE.md`）
- **時機重要性**：需要使用者在明確的時間點主動觸發，而非 Claude 自主決定
- **影響範圍**：文件變更影響整個 team 的領域共識，需謹慎

這是設計上的刻意選擇，有充分理由。

### zoom-out — disable-model-invocation: true 的原因

`zoom-out/SKILL.md` 的完整內容極短（僅 7 行），技能本體只有一句話：

> "I don't know this area of code well. Go up a layer of abstraction. Give me a map of all the relevant modules and callers."

`disable-model-invocation: true` 的原因在 SKILL.md 中**未有任何說明**。推測原因：
- 此技能會讓 agent 切換到「地圖模式」，改變整個對話的方向
- 若 Claude 自動觸發，可能在不恰當的時機打斷正在進行的開發流程
- 需要使用者主動表達「我想要更大視野」的意圖

但此推測未有任何文件支撐，屬於待確認事項。

## 5. 已知技術債

### 5.1 obsidian-vault — 路徑 Hardcode，不具通用性

**嚴重程度**：高  
路徑 `/mnt/d/Obsidian Vault/AI Research/` 使此技能在 Matt Pocock 的個人環境以外完全無法使用。最小修復方案：在 SKILL.md 開頭加入「詢問使用者 vault 路徑」的步驟，或改為讀取環境變數 `OBSIDIAN_VAULT_PATH`。

### 5.2 scaffold-exercises — 依賴 Matt Pocock 的個人 CLI 工具

**嚴重程度**：高（對非 aihero.dev 使用者）  
`pnpm ai-hero-cli internal lint` 對外部使用者來說是黑盒依賴。若無此工具，技能的第 4 步永遠失敗。技能描述中也未警告此限制，容易讓使用者困惑。

### 5.3 無版本管理機制

**嚴重程度**：中  
使用者無法固定到特定版本的技能，也無法接收安全更新通知。重新安裝會覆蓋本機修改（如 obsidian-vault 路徑客製化）。

### 5.4 無自動化測試

**嚴重程度**：中  
整個 repo 是純文件，沒有任何機制驗證 SKILL.md 的 frontmatter 格式正確（如 `name` 與目錄名稱一致、`description` 不超過 1024 字元、必填欄位齊全）。任何格式錯誤只有在實際使用時才會被發現。

### 5.5 部分技能缺乏失敗處理說明

**嚴重程度**：低  
`github-triage` 技能依賴 `gh` CLI，但 SKILL.md 未說明以下情況的處理：
- `gh` CLI 未安裝或未認證時
- GitHub API rate limit 被觸及時
- Issue 已被關閉時嘗試修改 label

其他依賴 GitHub 的技能（`triage-issue`、`to-prd`、`to-issues` 等）同樣有此問題。

### 5.6 AI 免責聲明僅為 Soft Constraint

**嚴重程度**：低  
`github-triage` 的 AI 免責聲明完全靠 Claude 遵循指令，無程式化強制機制。若 Claude 省略免責聲明，使用者不會得到任何提示。

建議確認：

- 是否有計劃提供不依賴 `ai-hero-cli` 的通用版本（例如只建立目錄結構，不跑 lint）？

SKILL.md 未解釋此設定的原因，建議加入一行說明以幫助使用者理解預期使用方式。

`github-triage` 的 AI 免責聲明目前完全依賴 Claude 遵循指令。是否有計劃透過 bash script 或 PostToolUse hook 驗證 comment 格式？
