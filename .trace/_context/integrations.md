# Stage 2.5 外部整合

## 概述

此 repo 本身沒有程式碼層級的外部整合（無 HTTP 呼叫、無 SDK 依賴）。技能**指引 Claude 呼叫**外部工具與服務，但這些呼叫是由 Claude 在執行技能指令時發起的，而非此 repo 的程式碼。

---

## 整合 1：GitHub（通過 `gh` CLI）

**使用的技能**：`github-triage`、`triage-issue`、`qa`、`to-issues`、`to-prd`、`request-refactor-plan`

### 呼叫方式

透過 `gh` CLI（GitHub 官方命令列工具）：
```bash
gh issue view <number>           # 讀取 Issue
gh issue create --title "..." --body "..."  # 建立 Issue
gh issue edit #N --add-label "..."          # 修改 label
gh issue comment #N --body "..."           # 新增留言
gh issue list --label needs-triage         # 列出 Issues
```

Repo 資訊推斷：`git remote` 自動推斷當前 repo（`github-triage/SKILL.md`：「Infer the repo from `git remote`.」）

### 失敗處理

**無明確的 retry/circuit breaker 規範**。技能指令沒有描述失敗時的處理，依賴 Claude 的自主判斷或 `gh` CLI 的錯誤輸出。

### 輸出格式規範

`github-triage` 有嚴格的 AI 免責聲明要求（`SKILL.md` AI Disclaimer 段落）：
```markdown
> *This was generated by AI during triage.*
```
**此免責聲明必須出現在每個 comment 的第一行**。

## 整合 2：Claude Code Agent Tool（sub-agents）

**使用的技能**：`design-an-interface`、`improve-codebase-architecture`、`triage-issue`、`qa`

### 呼叫方式

```python
# 平行 sub-agents（design-an-interface, improve-codebase-architecture）
Agent(subagent_type="Explore", prompt="...")

# 背景 sub-agent（qa）
Agent(subagent_type="Explore", run_in_background=True, prompt="...")
```

### 各技能的使用模式

| 技能 | Agent 用途 | 執行模式 |
|------|-----------|--------|
| `design-an-interface` | 生成 3+ 種截然不同的介面設計 | 平行（同時執行） |
| `improve-codebase-architecture` | 探索 codebase，找出架構摩擦點 | 前景 |
| `triage-issue` | 深入調查 codebase，找根因 | 前景 |
| `qa` | 學習領域語言，理解相關功能 | 背景（使用者繼續描述 bug 時） |

### Sub-agent 的設計約束（design-an-interface）

每個 sub-agent 獲得不同設計約束（`SKILL.md` 步驟 2）：
- Agent 1：「Minimize method count — aim for 1-3 methods max」
- Agent 2：「Maximize flexibility — support many use cases」
- Agent 3：「Optimize for the most common case」
- Agent 4（可選）：「Take inspiration from [specific paradigm/library]」

## 整合 3：Obsidian Vault（通過 bash 搜尋）

**使用的技能**：`obsidian-vault`

### 呼叫方式

```bash
# 搜尋筆記
find "/mnt/d/Obsidian Vault/AI Research/" -name "*.md" | grep -i "keyword"
grep -rl "keyword" "/mnt/d/Obsidian Vault/AI Research/" --include="*.md"

# 搜尋反向連結
grep -rl "\[\[Note Title\]\]" "/mnt/d/Obsidian Vault/AI Research/"

# 找 index notes
find "/mnt/d/Obsidian Vault/AI Research/" -name "*Index*"
```

**Vault 路徑**（hardcoded）：`/mnt/d/Obsidian Vault/AI Research/`
⚠️ 這是 Matt Pocock 個人環境的路徑，其他使用者必須修改。

## 整合 4：Claude Code hooks 系統

**使用的技能**：`git-guardrails-claude-code`

### 整合方式

透過 Claude Code 的 settings.json 設定 `PreToolUse` hook：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/block-dangerous-git.sh"
          }
        ]
      }
    ]
  }
}
```

### Hook 通訊協議

- **輸入**：JSON 從 stdin（Claude Code 傳入）
  ```json
  {"tool_input":{"command":"git push origin main"}}
  ```
- **允許繼續**：exit 0
- **阻止執行**：exit 2 + 錯誤訊息到 stderr

## 整合 5：@total-typescript/shoehorn npm 套件

**使用的技能**：`migrate-to-shoehorn`

### 整合方式

技能指引 Claude 安裝此套件並進行遷移：
```bash
npm i @total-typescript/shoehorn
```

**函式對照**：

| 原始 `as` 語法 | shoehorn 替換 |
|--------------|-------------|
| `{...} as Type` | `fromPartial({...})` |
| `{...} as unknown as Type` | `fromAny({...})` |
| 強制完整物件 | `fromExact({...})` |

## 整合 6：Husky + lint-staged + Prettier

**使用的技能**：`setup-pre-commit`

### 安裝流程

```bash
npm install husky lint-staged prettier --save-dev
npx husky init
```

### 建立的整合

```
git commit
    │
    ▼
.husky/pre-commit
    ├── npx lint-staged    → Prettier（格式化暫存檔）
    ├── npm run typecheck  → TypeScript 型別檢查
    └── npm run test       → 執行測試套件
```

`.lintstagedrc`：
```json
{"*": "prettier --ignore-unknown --write"}
```

## 外部整合的失敗處理摘要

| 整合 | 失敗處理策略 |
|------|-----------|
| GitHub (`gh` CLI) | ⚠️ 無明確規範，依賴 Claude 判斷 |
| Agent Tool | ⚠️ 無明確 retry，若 sub-agent 品質不佳由 main agent 重新派發 |
| Obsidian Vault | 找不到筆記時，Claude 應回報 |
| Claude Code hooks | exit code 2 = 攔截（Claude Code 平台處理） |
| shoehorn 安裝 | 依賴 npm，失敗時 npm 輸出錯誤 |
| Husky 安裝 | 依賴偵測到的 package manager |
