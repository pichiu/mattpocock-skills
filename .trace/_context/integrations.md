## GitHub CLI (`gh`) — 最廣泛使用的整合

### 讀取操作
```bash
gh issue view <number>        # to-issues/SKILL.md:14
gh issue list --label <label> # github-triage/SKILL.md:67
```

### 寫入操作
```bash
gh issue create --title "..." --body "..."   # triage-issue/SKILL.md:59, to-issues/SKILL.md:52
gh issue edit --add-label <label>            # github-triage/SKILL.md（隱含）
gh issue comment --body "..."                # github-triage/SKILL.md
gh issue close                               # github-triage/SKILL.md（wontfix 流程）
```

### AI 免責聲明（強制）
`github-triage/SKILL.md:13-15` 要求所有 AI 生成的 GitHub 評論必須在開頭加入：
```markdown
> *This was generated by AI during triage.*
```

### 失敗處理
Skills 沒有明確的 retry 或 circuit breaker 邏輯。假設 `gh` CLI 已正確認證，失敗會直接報錯給使用者。

| Skill | 派發方式 | 目的 |

## Obsidian Vault — 本地檔案系統整合

`obsidian-vault/SKILL.md` 定義了與 Obsidian 的整合：

```bash
# 搜尋筆記（obsidian-vault/SKILL.md:29-33）
find "/mnt/d/Obsidian Vault/AI Research/" -name "*.md" | grep -i "keyword"
grep -rl "keyword" "/mnt/d/Obsidian Vault/AI Research/" --include="*.md"

# 反向連結
grep -rl "\[\[Note Title\]\]" "/mnt/d/Obsidian Vault/AI Research/"
```

⚠️ 未驗證：Vault 路徑 `/mnt/d/Obsidian Vault/AI Research/` 是 Matt Pocock 個人 Windows + WSL 環境的硬編碼路徑，其他使用者需要修改。

**Obsidian 特有格式**：使用 `[[wikilinks]]` 語法，而非標準 Markdown 連結。

## 無明確錯誤處理的整合

這個 repo 中的 skills 幾乎沒有明確的錯誤處理邏輯，原因是：

1. 這是 prompt-based 系統，LLM 會根據情境靈活應對
2. Skills 假設外部工具（`gh`、`git`、`jq`）已正確安裝和設定
3. 唯一有顯式失敗處理的是 `block-dangerous-git.sh`（exit 2 表示阻止）

**`jq` 依賴**（`block-dangerous-git.sh:4`）：
```bash
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')
```
若 `jq` 未安裝，script 會靜默失敗（`exit 0`，即允許所有命令）。⚠️ 這是一個潛在的安全問題。
