# Stage 2.2 Data Flow

## 概述

此 repo 沒有傳統的 request/response 流程。「資料流」的概念在此 repo 中等同於：
1. 技能的**執行流程**（使用者意圖 → 技能載入 → Claude 執行 → 輸出）
2. 唯一 bash script 的**資料處理流程**

---

## 代表性 Use Case 1：`github-triage` 技能完整流程

這是最複雜的技能，具有狀態機、多種輸出、跨工具呼叫。

```
使用者呼叫 /github-triage
          │
          ▼
[1] 解析使用者意圖（自然語言）
    "Show me anything that needs attention"
    "Let's look at #42"
    "Move #42 to ready-for-agent"
          │
          ▼
[2] 根據意圖路由到對應工作流
    ┌─────────────┬───────────────┬──────────────────┐
    │ 概覽          │ 處理特定 Issue │ 快速狀態變更      │
    └──────┬──────┴───────┬───────┴────────┬─────────┘
           │              │                │
           ▼              ▼                ▼
    [2a] 查詢 GitHub   [2b] 收集 context  [2c] 套用 label
         unlabeled,        讀取 issue body    直接執行
         needs-triage,     + 所有留言
         needs-info        + codebase 探索
         → 分組顯示         + .out-of-scope/
                                │
                                ▼
                          [3] 提出建議
                              category: bug/enhancement
                              state: needs-triage/ready-for-agent/...
                                │
                                ▼
                          [4] 等待維護者決定
                          ┌────────────────────┐
                          │ ready-for-agent     │→ 寫 agent brief comment
                          │ ready-for-human     │→ 寫摘要 comment
                          │ needs-info          │→ 寫 triage notes comment
                          │ wontfix (bug)       │→ 寫說明 comment，關閉
                          │ wontfix (enhance)   │→ 寫 .out-of-scope/ 文件
                          └────────────────────┘
                                │
                                ▼
                          [5] 套用 label + 執行動作
                              gh issue edit #N --add-label "..."
                              gh issue comment #N --body "..."
```

**輸入**：使用者的自然語言描述 + GitHub repo（透過 `git remote` 推斷）
**輸出**：
- GitHub Issue 的 label 變更
- GitHub Issue 的 comment（含 AI 免責聲明 `> *This was generated by AI during triage.*`）
- `.out-of-scope/*.md` 文件（wontfix enhancement 時）

**每個 comment 的強制結構**（`github-triage/SKILL.md`，AI Disclaimer 段落）：
```markdown
> *This was generated by AI during triage.*

[實際內容]
```

## 代表性 Use Case 2：`tdd` 技能執行流程

最常見的開發工作流程，展示了 Claude 如何被引導執行 TDD。

```
使用者呼叫 /tdd (或 Claude 自動偵測到 TDD 情境)
          │
          ▼
[1] Planning 階段
    詢問使用者：
    - 介面如何改變？
    - 哪些行為要測試？
    - 辨識深度模組機會
    - 設計可測試介面
    - 列出要測試的行為清單
    - 取得使用者同意
          │
          ▼
[2] Tracer Bullet（第一個 RED-GREEN 循環）
    RED:   寫第一個測試 → 測試失敗
    GREEN: 寫最小程式碼 → 測試通過
          │
          ▼
[3] 增量 Loop（對每個剩餘行為）
    RED:   寫下一個測試 → 失敗
    GREEN: 最小程式碼   → 通過
    重複...
          │
          ▼
[4] Refactor 階段（所有測試通過後）
    - 提取重複
    - 深化模組
    - 套用 SOLID 原則
    - 每次重構後執行測試
```

**關鍵資料轉換規則**（來自 `tdd/SKILL.md`）：
- ❌ 不允許水平切片（先寫全部測試，再寫全部實作）
- ✅ 垂直切片：一個測試 → 一個實作 → 重複

## 代表性 Use Case 3：`block-dangerous-git.sh` 執行流程（唯一可執行程式碼）

```
Claude Code 準備執行 Bash tool
          │
          ▼
[PreToolUse hook 觸發]
          │
          ▼
[block-dangerous-git.sh 接收 JSON 輸入]
stdin: {"tool_input":{"command":"git push origin main"}}
          │
          ▼
INPUT=$(cat)                    # 讀取完整 JSON
COMMAND=$(jq -r '.tool_input.command')  # 解析 command 欄位
          │
          ▼
for pattern in DANGEROUS_PATTERNS
  grep -qE "$pattern" <<< "$COMMAND"
          │
    ┌─────┴─────┐
    │ 找到危險模式 │            │ 沒找到危險模式
    ▼           ▼
echo "BLOCKED..." >&2      exit 0
exit 2                     (允許 Claude 繼續)
(Claude 收到 exit 2，
 知道指令被攔截)
```

**輸入**：JSON (來自 Claude Code PreToolUse hook)
```json
{"tool_input":{"command":"git push origin main"}}
```

**輸出（被攔截時）**：
```
stderr: BLOCKED: 'git push origin main' matches dangerous pattern 'git push'. 
        The user has prevented you from doing this.
exit code: 2
```

**輸出（允許時）**：
```
exit code: 0
```

## 技能間的資料傳遞

技能之間不透過程式呼叫傳遞資料，而是透過**約定的文件格式**：

```
domain-model → CONTEXT.md (術語表)
             → docs/adr/*.md (架構決策)
             
github-triage → .out-of-scope/*.md (拒絕的功能請求)

ubiquitous-language → UBIQUITOUS_LANGUAGE.md

improve-codebase-architecture 讀取 CONTEXT.md (domain-model 的輸出)
                               讀取 docs/adr/ (domain-model 的輸出)
```

這形成一個**非同步、文件驅動的資料流**：各技能透過在 codebase 中讀寫特定格式文件來「溝通」，而非直接 API 呼叫。
